# دليل تسليم مشروع Clarity

هذا هو دليل تشغيل نسخة التسليم **GP**. افتح هذا الملف أو `README.md` من داخل المجلد. يحتوي المشروع التطبيق والواجهة والاختبارات والوثائق؛ لا يحتاج مجلدات مشروع إضافية.

## شكل المشروع

```text
GP/
├── .github/                 # إعدادات GitHub Actions وقالب طلب التغيير
├── docs/                    # دليل التشغيل والمتطلبات والخصوصية والتقييم
├── evaluation/              # بيانات التقييم والقواعد المرجعية
├── requirements/            # متطلبات Python المثبتة
├── scripts/                 # إعداد وتشغيل وفحص MySQL والاختبارات
├── src/governance/          # API والوكيل والجودة والخصوصية والتخزين
│   ├── providers/            # Qwen المحلي وGemini وOpenAI
│   └── static/               # واجهة HTML وCSS وJavaScript
├── tests/                   # اختبارات المشروع
├── .env.example              # نموذج إعدادات بلا أسرار
├── pyproject.toml            # إعداد حزمة Python وأدوات التطوير
├── run.ps1                   # تشغيل التطبيق
└── submission-manifest.json  # بصمات ملفات نسخة التسليم
```

## تشغيل التطبيق

يلزم Windows وPython 3.11 أو أحدث. افتح PowerShell داخل **GP** وشغّل:

```powershell
.\run.ps1
```

ينشئ التشغيل الأول بيئة Python ويثبت المتطلبات، ويحتاج اتصالًا بالإنترنت لتنزيل الحزم. افتح [Clarity Studio](http://127.0.0.1:8000). تبدأ الواجهة بالعربية والوضع الداكن، ويمكنك تبديل اللغة أو المظهر من الشريط العلوي. تظهر صفحات المخطط والمراجعة وقاموس البيانات والجودة والتقييم والخصوصية في القائمة الجانبية. التطبيق مخصص لمستخدم واحد على الجهاز المحلي.

## الاتصال ببيانات MySQL

التطبيق لا ينشئ قاعدة بيانات المصدر ولا يكتب فيها. يلزم مصدر اختبار وحساب MySQL للقراءة فقط. لا تستخدم حساب المدير أو بيانات قاعدة عمل حقيقية.

لإعادة إعداد قاعدة Sakila العامة المعزولة على هذا الجهاز، اتبع خطوات [فحص MySQL العام](public-data-test.md). يتطلب ذلك تنزيل ملفات MySQL وSakila وإعدادها أول مرة؛ لا تُضمّن الملفات التنفيذية أو كلمات المرور أو مجلد قاعدة البيانات في التسليم. بعد إعداد المصدر، جهّز قيم MySQL في `.env.local` محليًا، أعد تشغيل Clarity، واختر **MySQL** ثم **Connect source**. تعرض الواجهة عدد الجداول والأعمدة المتصلة.

## استخدام Qwen المحلي

المزوّد المحدد للمشروع هو `local` والنموذج المضبوط هو `qwen3-4b-instruct-2507` عبر LM Studio. نجحت سابقًا اختبارات توليد النص واستدعاء الأدوات وإرجاع مقترحات JSON عبر محوّل المشروع. لا يلزم تغيير النموذج أو إعداداته الحالية. على جهاز جديد، انسخ `.env.example` إلى `.env.local` واضبط اتصال MySQL؛ إعدادات Qwen الافتراضية موضحة في [الإعدادات](configuration.md#use-local-qwen).

لتشغيل الوكيل، تأكد أن خادم LM Studio المحلي يعمل على `127.0.0.1:1234`، ثم اختر **Adaptive agent** واضغط **Start inspection**. سيبدأ استخدام النموذج عند بدء الفحص فقط؛ فتح الصفحات وفحص الجاهزية لا يرسلان طلبات إليه. لا يحتاج هذا المسار مفتاحًا سحابيًا.

قبل الفحص، اختر حدود الوقت والرموز وعدد استدعاءات الأدوات من **Inspection limits**. فحص الجاهزية محلي ولا يختبر اتصال النموذج. يحتاج المسار الثابت على Sakila كاملة إلى 91 استدعاء أداة على الأقل، بينما الحد الافتراضي 40؛ عدّل الميزانية قبل اختيار هذا المسار. يختلف الوقت وإمكان إنهاء التحليل حسب الجهاز والميزانية. لا تعني عبارة الإعداد موجود أن الفحص اكتمل.

## سير العمل

1. اربط MySQL أو اختر العرض الاصطناعي الاختياري.
2. للفحص الفعلي، شغّل LM Studio، ثم اختر الوكيل التكيفي واضغط **Start inspection**. العرض الاصطناعي لا يستخدم النموذج ولا يمثل نتيجة فعلية.
3. راجع كل مقترح وأدلته وافتراضاته، ثم اعتمده أو عدّله أو ارفضه.
4. اضغط **Run approved checks** عندما تريد تشغيل القواعد المعتمدة على المصدر.
5. راجع تقرير الجودة والتغطية والنتائج غير المحسومة، ثم صدّر القاموس أو التقارير عند الحاجة.

تبقى القراءة من المصدر فقط. يحجب مرشح الخصوصية قيم العينات الخام والتعليقات وبيانات الاتصال عن النموذج، وتبقى أسماء المخطط والإحصاءات المجمعة ضمن الأدلة المسموح بها. القواعد لا تعمل إلا بطلب صريح بعد اعتماد بشري. لا تخلط الواجهة العرض الاصطناعي بنتائج فحص النموذج.

## التسليم والخصوصية

يمكن تسليم مجلد **GP** كاملًا أو ملف **GP.zip**. لا يحتويان `.env.local` أو مفاتيح API أو كلمات مرور MySQL أو قاعدة البيانات أو خادم MySQL أو البيئة الافتراضية. تُنشأ ملفات التشغيل داخل `data/` على الجهاز المستلم. يحتوي `.env.example` قيمًا افتراضية وأسماء إعدادات؛ حقول كلمات المرور والمفاتيح فارغة.

تمت مراجعة الواجهة بالعربية والإنجليزية وفي المظهرين، وعرض مخطط Sakila الحقيقي: 16 جدولًا و90 عمودًا و22 علاقة معلنة. النتائج التقنية على Sakila لا تقيس دقة الوكيل. أدوات الدراسة متاحة، لكن إعداد المرجع البشري واعتماد معايير القبول وإجراء التجارب المستقلة وقياس وقت المراجعة ما زال مطلوبًا؛ راجع [حالة المشروع](status.md) و[قائمة قبول MVP](acceptance.md).

هذا المجلد جذر مشروع مستقل وجاهز للرفع إلى GitHub بترخيص MIT. اتبع [دليل الرفع](github-upload.md) قبل أول commit.

## عند حدوث مشكلة

- إذا تعذر الاتصال بـMySQL، راجع قيم `MYSQL_*` وحالة الخادم وصلاحيات حساب القراءة فقط، ثم أعد تشغيل Clarity بعد تعديل الإعدادات.
- إذا فشل طلب الفحص، راجع حالة التشغيل المعروضة وحدود الفحص والخادم المحلي. لا تعني نتيجة `budget_exhausted` أن التحليل الكامل اكتمل؛ يمكن زيادة الحدود صراحة أو اختيار نطاق أصغر من المصدر.
- إذا أصبح تقرير الجودة قديمًا بعد تعديل القواعد المعتمدة، أعد تشغيل **Run approved checks** لتوليد تقرير يطابق النسخ الحالية.

تُحفظ المراجعات والنتائج في `data/governance.db`. بعد إعادة التشغيل، يمكنك عرض آخر مخطط MySQL ومقترحاته وقاموسه وتقريره المحفوظ، مع ظهور المصدر غير متصل. يلزم الاتصال لبدء فحص جديد أو تشغيل قواعد؛ ينشئ الاتصال نطاق عمل جديدًا ويحفظ السجلات السابقة في التخزين. احتفظ بنسخة خاصة من `data/` و`.env.local` بعد إيقاف التطبيق إذا احتجت نقل حالة العمل؛ هذه الملفات غير مشمولة في حزمة التسليم العامة.

## التطوير والاختبارات

تحتاج اختبارات الواجهة إلى Node.js. للمطورين:

```powershell
.\scripts\setup.ps1 -Dev
.\scripts\check.ps1
```

تفاصيل إعداد قاعدة الاختبار والمزوّد وحدود التشغيل في [الإعدادات](configuration.md)، والنتائج المعتمدة في [حالة المشروع](status.md).
